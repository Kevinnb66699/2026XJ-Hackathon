# 知适：把讲义里的「如果」，改成「你」

> 杭州学军中学「回响 · 48H 青年创造营」Echo 赛道作品（2026-10-01 22:00 至 10-03 24:00）
>
> 在线体验：**https://zhishi.jiling.chat**（首页两个入口：「我是学生」「我是老师」。「我是学生」进完整的学生流程。比赛期间的「演示模式」和评委模式 10-04 已下线，评委卡上的二维码 `#/judge` 会回到首页）
>
> 本仓库文档里的「队长」指范存凯（负责技术）；平台上登记的队长是吕芊凝。

老师写一份外刊讲义，全班拿到的是同一份 PDF。讲义里写着「如果对 pending 一词不够熟悉，可能会造成理解困难」，但一份 PDF 只能对全班写「如果」。

**知适**让每个学生读到写给自己的那一份：

- **原文一字不改**，老师的教学目标一个不少。
- 只在**你卡住的地方**搭一架会自己撤掉的「读懂梯子」：谁 → 做了什么 → 拆开每一块在说什么 → 最后才是译文，原句一直在上面（老师上传的文章 10-03 下午起也是这样；之前上传的仍是正常语序、简单英文）。
- 你读到的表达，要在你自己的写作里用出来（表达链）。
- 全班的卡点回响给老师，变成一张「今天点评这几个人」和卡点热力图。
- 老师端还有：「刚刚」（实时数据每 5 秒自动更新，列出刚发生的答错、开梯子和第一次就答对）、「全班情况」（规则直接算出的几条汇总，点一下可以让 AI 起草下一节课的教学建议）、读懂轨迹、「下一届的起点」建议名单和预览、粗读段意题统计。
- 老师可以**粘贴任意一篇英文文章**生成一份讲义（AI 起草、程序校验、老师预览后发布），学生扫码就能用。实测几篇 4 段的短文，12–18 秒生成完。生成后老师可以按句写讲解（可选），也可以点「AI 起草讲解」：点一次，AI 就在还没有讲解的句子里把值得讲的（长、结构复杂的句子，有关键生词挡住理解的，作者表明观点或转折的）都写一稿，简单好懂的跳过，草稿只填进编辑区、标着「AI 草稿，待你确认」，老师看过、改好、点保存，学生才看得到（服务器 8 句一批、最多两批同时起草，按钮上显示「第 x / y 批」，句子多的文章要一两分钟；本地用真实模型实测，14 句的文章分 2 批、12 秒、起草 11 句）。只有上传这篇文章的老师登录后能写讲解，拿到学生链接的人改不了。写了讲解的句子和演示讲义一样：有题、又不是重点句的，第一次就答对、没开梯子的同学讲解先收起；讲解里有一句带「如果」、照原句写法点名这一句的某个注释词、不带语法术语，这个词又正好是他不认识的，他答题前就多一张「给你」便签；没写讲解的句子两样都没有。词汇卡里也不混入假词（内置讲义会混 1 个编出来的词，它的例句是学生用手机、刷视频这类话题，换一篇文章就对不上）。AI 起草的原句题（题干、选项、正确答案）、梯子（第 1 步「谁」「做了什么」必须照抄原句，第 2、3 步，难词的中文意思）和段意题，老师也能在同一页直接改，同样只有上传的老师登录后能改：服务器按和入库同样的规则再校验，不合格的按字段标红、一处都不写；学生重新打开就看到新的，已经答过的记录不变。「先猜一猜」词题不能改，选项和难词不能增删。

演示原来用的是一份购买的五天外刊精读讲义（主题：青少年社交媒体禁令）。**10-04 起，购买讲义的原文和衍生数据已从仓库当前版本移除（版权），演示改用团队自写的迷你讲义**（`tests/fixtures/mini-handout.ts`，2 段 5 句；正式的新演示文章以后再做），旧链接 `?h=social-media` 会打开迷你讲义。学生端：问卷 → 粗读（先通读全文，再答每段一题；全答对后看「这篇文章是怎么写的」，每段起什么作用）→ 词汇（先猜后看）→ 精读（读懂梯子）→ 写作（表达链，写之前有原文里「可以借的写法」）→ 反馈。题目和选项都用英文，和讲义里的「细节理解」题一致；词义题是英文题干、中文选项（这两句说的是原来的购买讲义；迷你讲义的题目是中文，也没有「这篇文章是怎么写的」和「可以借的写法」；它的 6 个词没有词性和英文释义，「先猜一猜」只有 pending、blanket 两道）。

     重点句、填空、老师精讲）                          纯函数，按直接证据适配支架              卡点热力图
  → pipeline/draft.ts     大模型按段起草（梯子、    → 写作：规则检查用没用上 +

  → pipeline/validate.ts  校验器（原文子串、出处、     只判断用得对不对、指出可能的语法问题，不改写）
     语法术语、必练覆盖）
  → AI 补全（pipeline/ai-edits.json：Claude 补写的词卡内容、梯子第 2、3 步和文章结构，还没人工校对；每次入库在人工修订之前套用）

  → data/handouts/<id>.json

10-04 起，上图老师侧用到的购买讲义数据（`data/raw/`、`data/extract/`、`data/handouts/social-media*.json`、`pipeline/cache/`、`pipeline/ai-edits.json`、`pipeline/human-edits.json`、`pipeline/report.md` 和 `docs/` 里的校对表）已从仓库移除（版权）；管线代码保留，缺数据时给出中文提示。

- **AI 主要在老师那一侧**：每份讲义入库时起草一次，所有输出都经过校验器检查；学生侧的个性化是规则，不调用 AI，按学生调用模型的只有写作检查（所以成本不是和学生人数无关）。原来的演示讲义（购买讲义，10-04 起已移除）里模型起草的内容还逐条做过人工校对（231 条人工修订），并附老师原话作为出处；词卡上后补的内容里，35 个词的词性和英文释义、34 道猜词题由 Claude 起草，只经过独立 agent 核对，还没人工校对（15 个核心词的词性和英文释义照老师 Day 1 的核心词汇表）；21 架梯子新的第 2、3 步（拆开、译文）也由 Claude 起草，经 agent 和脚本核对，还没人工校对（见 AI_USAGE.md）。
- **学生侧是确定性规则**：可解释，没有延迟，不会直接给答案，也不存「已掌握」标签。
- **运行时调用 AI 的有四处**：老师上传文章时起草读懂支架（deepseek-v4-pro，一篇文章起草一次：按段并行调用模型，失败的段再试一次，不合格的输出由校验器剔除，老师预览后才发布；没填标题时同时请模型起一个英文标题（像外刊标题，2–8 个词），起不成就用原文第一句）；学生侧的写作检查，判断表达用得对不对，并指出最多 3 处可能的语法问题（只引学生原话里的几个词、标出类型、提示该检查什么，不给正确写法），绝不改写学生的句子，8 秒超时后回落到规则检查；老师端的「教学建议（AI 起草）」，老师点按钮才调用，只发全班汇总数据（人数、次数、句子原文、老师精讲、结构、词、段意题题干，不发学生编号和作答原文），依据里的数字、句子编号、段落在汇总里找不到，或者用中文写人数比例（九成、一半等），整条丢掉；数字配错了句子查不出来。同一份汇总只调用一次。第四处是上传页的「AI 起草讲解」，老师点按钮才调用（deepseek-v4-pro，关闭思考）：点一次就给还没有讲解的句子里值得讲的都写讲解草稿，简单好懂的跳过（按段落顺序 8 句一批、同时最多 2 批，每批 60 秒超时；有的批没起草成，就先给成功的草稿，并提示另有几句可以过一会儿再点；次数按点击算），带语法术语的、在「如果不认识 X 一词……」那一句之外用了「如果」的整条丢掉（「给你」便签在学生答题前就引这一句）；草稿不保存，老师看过、改好、点保存才写进讲义，学生才看得到；保存后和老师自己写的讲解一样对待（包括教学建议汇总里的「老师精讲」）。

## 运行

需要 Node ≥ 16.14。

```bash
npm install
npm run dev          # 前端，http://localhost:5173
npm run server       # 后端，127.0.0.1:8787（写作检查需要 .env 里的 tokenspace_apikey）
npm run check        # 类型检查 + 测试 + 讲义校验 + 构建（构建同时输出 dist-server/article.mjs，后端上传要用）
```

老师上传文章：先 `npm run build`，再运行后端，打开 `http://localhost:5173/#/upload`（需要 `.env` 里的 tokenspace_apikey）。

讲义入库（老师侧）：10-04 起购买讲义的原文和衍生数据已从仓库移除（版权），下面四条命令在缺数据时会说明原因并退出；要重跑得把本地备份放回原路径（不要再提交：`.gitignore` 只忽略了被删的那几个具体文件，`pipeline/ai-edits.json`、`pipeline/human-edits.json`、`pipeline/report.md` 是管线的通用路径，没有忽略，放回后不要 `git add`）。`npm run validate` 现在校验仓库里的迷你讲义。`pipeline/extract.ts` 的 `extractHandout` 和 `pipeline/overrides.ts` 是照这份购买讲义的版式写的，已冻结：原来的测试都依赖讲义原文，随数据一起删了，现在没有测试，缺数据也跑不了。

```bash
npm run ingest -- --replay   # 只用 pipeline/cache 里的模型响应复跑，不联网，可复现
npm run ingest               # 调用大模型重新起草（需要 .env 里的 tokenspace_apikey）
npm run review               # 导出人工校对表 docs/校对表.csv
npm run review:import -- docs/校对表-定稿.csv --dry   # 把校对结果转成人工修订，先试套校验；去掉 --dry 才写文件
```

## 学生侧的硬规则（写在测试里）

- 句子原文与讲义逐字一致；
- 老师的必练项一个不少：重点句（老师讲义里的打卡翻译句；上传的文章由程序挑）的讲解不会因为答对就收起；核心词一定在词汇卡片里，永远不会被标成「可跳过」（学生标了「认识」、先猜后看又没猜错的，精读里不再加注释）；写作要求的表达一定出现在写作里；
- 题目选项数不减少；
- AI 起草的文字（梯子、题目、注释、写作理由和语法提示、讲解草稿）不出现语法术语（写作的语法问题只标时态、冠词这类类型）；老师讲解按老师保存的原样显示（老师自己写的，或老师看过、改过的 AI 草稿）；
- 写作反馈（包括语法问题）不给改写后的句子；
- 不显示任何等级标签。
