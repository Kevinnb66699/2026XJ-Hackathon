# 老师上传文章：设计与接口约定

> 目标：老师粘贴任意一篇英文文章（标题可不填，不填由 AI 起一个；可选填必练词、教学重点），AI 起草读懂支架，程序校验，老师预览后发布，学生扫码就能用。比赛期间评委可以用自己手机里的文章当场试；10-04 起上传只对受邀老师开放，随后改成老师账号（邀请码注册，用户名 + 密码登录）。
> 三部分（管线 / 后端 / 前端）并行开发，**接口以本文为准**。

## 流程

1. 老师先登录（`#/login`），在 `#/upload` 粘贴文章，提交。比赛期间谁都能体验；10-04 比赛结束后改成**只对受邀老师开放**，现在是老师账号：知适团队发邀请码（服务器 `.env` 的 `UPLOAD_INVITES`，见 `deploy/README.md`「发邀请码」），老师用它注册一个账号（一个码一个账号），之后用户名 + 密码登录，换设备也能用。
2. 后端建一个生成任务，立即返回 `jobId`，讲义记在这位老师名下（meta 的 `owner`）；前端每 1.5 秒查一次进度（切句 → 起草第 x / n 段 → 修正 → 校验）。
3. 生成完成：讲义存到服务器，显示入库报告（多少梯子、题目、注释，被校验拦下了什么），可以先预览学生端。
4. （可选，发布前后都行）老师按句写讲解，或点「AI 起草讲解」请 AI 给还没有讲解的句子写一稿（点一次就把值得讲的都起草，简单好懂的跳过；句子多时分批起草，按钮上显示「第 x / y 批」）。草稿只填进编辑区、标「AI 草稿，待你确认」，老师看过、改好，点「保存讲解」才存进讲义，学生才看得到（保存就算老师认可）。只有上传这篇文章的老师登录后能写讲解（见下文「老师账号」）。写了讲解的句子和演示讲义一样：讲解在学生答完这一句的题后显示，没有题的句子直接显示；有题、又不是重点句的，第一次就答对、没开梯子的学生讲解先收起；讲解里有一句带「如果」、照原句写法点名这一句的某个注释词、不带语法术语，这个词又正好是他不认识的，他答题前就会多一张「给你」便签，引的就是这一句，所以这一句不能写词义。没写讲解的句子两样都没有。已经打开页面的学生要重新打开才看得到新讲解。
   同一页下面还能改 AI 起草的原句题、梯子和段意题（10-03，提交 e59f79d）：同样只有上传的老师能改，服务器按入库的规则再校验，不合格的按字段标红、一处都不写（见下文「改题目和梯子」）。
5. 老师点「发布」，先勾选发布到自己的哪些班（班级在 `#/classes` 建、导入名单，见下文「班级和座号」；一个班都没有时提示先去建一个班；只有上传的老师能发布；没发布的讲义学生打不开）。发布后每个班一张二维码和学生链接（`/?h=<讲义 id>&c=<班级 id>#/student`），标明班级名，以及这个班的老师端链接（`/?h=<讲义 id>&c=<班级 id>#/teacher`）；已发布的讲义可以「改发布的班级」再发布一次（评委模式 10-04 已下线）。
6. 学生扫本班的码进来，第一次选自己的座号（只显示座号和「已有人」，没有姓名），拿到一个 6 位找回码；之后作答记在这个座号上，老师端按班看，称呼是「07 张三」。换手机时用座号 + 找回码找回，找回码丢了由老师在班级页给这个座号换一个。

## 一、管线：`pipeline/article.ts`

```ts
export interface ArticleInput {
  title: string           // 可以为空：请模型起一个英文标题（titleByModel），失败时用 deriveTitle 取原文第一句
  text: string            // 英文原文，段落之间空一行（没有空行时按单个换行分段）
  mustWords?: string[]    // 老师必练词（可选）
  checkIns?: string[]     // 重点句（可选，从原文复制，可以只是句子的一部分；上传页已不再填写，只为旧页面保留）
  focus?: string          // 教学重点（可选，自由文字，交给模型参考）
}
export type ArticleProgress =
  | { stage: 'split'; message: string }
  | { stage: 'draft'; done: number; total: number }
  | { stage: 'repair' | 'validate'; message: string }
  | { stage: 'done' }
export interface ArticleReport {
  paragraphs: number; sentences: number
  ladders: number; questions: number; gists: number
  words: number; guesses: number; expressions: number
  checkIns: string[]                              // 最终的重点句 id
  mustWords: { term: string; found: boolean }[]   // 老师必练词有没有在原文里找到
  repaired: string[]; dropped: string[]; warnings: string[]
  errors: number; model: string; seconds: number
}
export class ArticleError extends Error {}        // message 是给老师看的中文
export function splitArticle(text: string): { n: number; sentences: { id: string; text: string }[] }[]
export async function titleByModel(cfg: LlmConfig, text: string): Promise<string> // 没填标题时请模型起的英文标题
export function deriveTitle(text: string): string // 模型起不成时的标题（原文第一句）
export async function buildFromArticle(input: ArticleInput, opts: {
  id: string                                      // 讲义 id，形如 up-xxxx
  llm: LlmConfig
  onProgress?: (p: ArticleProgress) => void
  draft?: (p: ParagraphInput, focus?: string) => Promise<{ data: DraftParagraph; model: string }> // 测试时注入
}): Promise<{ handout: Handout; report: ArticleReport }>
```

- **标题**：没填就请模型起一个英文标题（issue #23；#26 从中文改成英文，提示词 `title-v2`，送整篇原文，和起草同时进行），像外刊文章的标题（提示词要 2–8 个词，比如「Gardens Grow in Schoolyards」）。校验：不超过 60 个字符，2–10 个英文单词，只能用英文字母、数字和常见标点（不能有中文、双引号和换行，撇号可以），不合格时让模型重写一次，单次限时 20 秒。模型超时、出错或两次都不合格，就用第一段的第一句，也就是 S01（分段规则见上、切句规则同下；段落之间有空行时，硬换行粘贴的段落也取整句）；超过 60 个字符就在词的边界截断、加「…」（连「…」不超过 60）。讲义标题、写作题目、meta、「我上传过的」列表都用它。
- **原文一字不改**：段内的换行合并成一个空格，其余字符原样保留。
- **限制**（超出就抛 `ArticleError`）：全文 200–8000 字符；英文字母要占多数；最多 12 段、60 句；单句不超过 400 字符；必练词最多 20 个，重点句最多 8 句。
- **切句**：在 `. ! ?`（后面可跟引号或括号）之后、下一个字符是大写字母、数字或引号的位置切开；Mr. / Dr. / U.S. / e.g. 等缩写不切。
- **起草**用新的提示词（版本 `article-v1`），不动现有讲义的 `draft-v1` 缓存：
  - 原句题、段意题的题干和选项都用英文（B1），正确项必须改写，不能照抄原句关键词；选项长度接近；
  - 先猜后看：题干 `What does “X” most likely mean here?`，两个选项用中文；
  - 学生端的中文和英文都不能有语法术语（中文见 `shared/terms.ts`；英文避免 clause / inversion / appositive / subject / predicate / grammar）；
  - 结构标签 `tag` 由模型按自己的分析填写（没有老师句子分析）。
- **重点句**（字段 `checkIn`；演示讲义里是老师的打卡翻译句，界面上 10-03 起叫「重点句」，issue #24）：上传页不再填写（10-02，issue #7），所以一般都是自动挑。老师给了就按原文匹配（忽略大小写和多余空白），匹配不到的写进 warnings。没给就自动挑：有梯子和原句题的句子里取最长的，最多 3 句，尽量分散在不同段落。重点句是 `tier: 'must'`、`checkIn: true`。
- **必练词**：用 `findForms` 在原文里找，找到的交给模型（必须出注释），然后标 `teacherCore: true`、`tier: 'must'`。
- **表达**：用模型起草的表达，匹配规则用 `patternFor` 生成。写作要求取前 3 个，写作题目为「用这篇文章学到的表达写 2–3 句：<标题>」。
- **校验**：照 `ingest.ts` 的流程，先用 `repairLadderL1` 自我修正，再用 `validateHandout` 校验，不合格的模型产出自动剔除并写进 `dropped`。最后不能有 error。
- **讲义字段**：`rights` 写「老师上传的文章，仅供本班学习使用」，`sources` 为空，`day` 统一为 2。
- **构建**：`npm run build` 额外输出 `dist-server/article.mjs`（vite SSR 构建，zod / undici 走外部依赖），Node 20 能直接 `import()`。`dist-server/` 不进 git。

| GET | `/api/my-progress?h=&c=` | 请求头 `X-Student-Token` | `{events, ai}`：这个座号的 `sid` 在这份讲义里的全部事件；token 不对 `401 {error:'找不到你的座号记录，请重新扫码'}` |
| GET | `/api/notes-drafts/:draftId` | | `{status:'running', done, total}`（已完成的批数 / 共几批）或 `{status:'done', notes: {S03: '…', …}, model}`（AI 起草的讲解，只回给老师当草稿，不写进讲义；模型给的是空列表时 `notes` 是 `{}`；有的批没起草成时多一个 `message:'另有 N 句这次 AI 没能起草，可以过一会儿再点一次「AI 起草讲解」。'`）或 `{status:'error', error:'AI 起草暂时不可用，可以先自己写'}`；`draftId` 是 24 位随机十六进制，只有发起起草的老师能查，别人（包括没登录）、找不到都是 `404` |

要登录的 POST 和注册、登录、退出都只收 `Content-Type: application/json`，别的 `415 {error:'请求格式不对'}`；不加 CORS 头。

- **防滥用**：要登录（账号要邀请码注册，见下文「老师账号」）；同一时间只跑一个任务；同一位老师每小时最多 5 篇；全站每天（北京时间）最多 60 篇。没有公开列表；没发布的讲义只有上传它的老师登录后能打开，发布后拿到链接就能打开。
- **存储**：`<dataDir>/handouts/<id>.json` 存讲义，`<id>.meta.json` 存 `{id,title,createdAt,published,report,owner,classes?}`（`title` 取讲义的标题，`owner` 是上传的老师 id，`classes` 是发布到的班级 id，发布时写；发布时改 meta 也是先写临时文件再改名）。任务只放在内存里，保留最近 20 个；同一时间只跑一个任务。
- **老师讲解**：存在讲义每一句的 `teacherNote`（和演示讲义同一个字段，不记哪几条是 AI 起草的），学生端照演示讲义的规则收起讲解、给「给你」便签。同一份讲义的保存排队，每次写一个随机名字的临时文件再改名，学生这时打开也不会读到半份。
- **改题目和梯子**（`/edits`，10-03）：老师能改原句题（题干、选项、正确答案）、梯子（第 1 步「谁」「做了什么」，第 2、3 步，难词的中文意思）和段意题；规则和校验器一致：第 1 步必须是原句原话，选项 2–4 个、不空、不重复，答案序号在范围内，题目、选项、梯子里不能有语法术语（`shared/terms.ts` 那张表；老师讲解不受此限）。不能改的：「先猜一猜」词题、注释词；不能增删选项和难词。改过的块来源记成 `{by:'human', reviewedBy:'teacher'}`。和 `/notes` 排同一条保存队；学生已经答过的记录不变。
- **老师账号**（替换 10-04 的编辑口令 `editKey`，口令只存在上传那台浏览器里，换设备就用不了）：讲义 id 就在学生链接里，所以光有 id 不能写讲解、发布、看全班记录，都要是上传它的老师登录。
  - 注册：邀请码（`UPLOAD_INVITES`，逗号分隔，少于 8 个字符的不用；没配置就谁都不能注册；比对的是 sha256 哈希，每个码都比一遍）+ 用户名 + 密码 + 称呼（可选）；一个码只能注册一个账号（账号上记码的 sha256，码本身不存）。先查邀请码再查字段和用户名，没有邀请码的人试不出哪些用户名被占了。用户名去首尾空白后转小写，3–32 个字符，只能是 `a-z 0-9 _ . -`，以字母或数字开头；密码 8–128 个字符，不能和用户名一样；称呼最多 20 个字、不能有控制字符，空就用用户名。不收手机号、邮箱。
  - 登录：用户名 + 密码；用户名不存在、密码不对都是同一个 401，用户名不存在时也对一个假哈希跑一遍 scrypt。同一用户名 15 分钟内失败 10 次先锁住（成功登录清零），登录 + 注册全站每分钟最多 60 次（限 scrypt 的 CPU），都只记在内存。
  - 存储：`<dataDir>/accounts.json` 存 `{teachers:[{id:'t-'+12 位十六进制, username, name, passwordHash:'scrypt$N$r$p$盐$哈希', createdAt, inviteHash, sessionsValidAfter?}]}`（scrypt N=16384、r=8、p=1，16 字节盐，64 字节输出，异步计算）；`<dataDir>/sessions.json` 存 `{sha256(token): {teacher, createdAt, expiresAt}}`，token 本身不落盘。两个文件都是写临时文件再改名、同一个文件的写排队；服务器缓存一份，按文件的 mtime / inode 重新读（团队命令行工具会直接改 `accounts.json`）。
  - 会话：cookie `zhishi_session`（32 字节随机十六进制；HttpOnly、SameSite=Lax、Path=/api、Secure，`COOKIE_INSECURE=1` 时不带 Secure，只给本机 http 调试）。30 天到期、不续期，写盘时顺手删掉过期的；退出时删掉服务器上的会话。重置密码时设 `sessionsValidAfter`，在它之前建的会话一律作废。
  - 权限：需要老师身份的接口没登录 401；登录了但讲义不存在 404；不是自己上传的 403（「只有上传这篇文章的老师能……」）。查进度、查起草结果只有发起的老师能查，别人和找不到一样 404；没发布的讲义别人读也是 404。账号功能之前上传的讲义 meta 里没有 `owner`（包括带 `editKey` 的），谁都不能写讲解、改题目、发布，也看不了学习记录；已经发布的照旧谁都能读。
  - 要登录的 POST 和注册、登录、退出只收 `application/json`（CSRF：别的网站用表单跨站提交带不上这个类型；cookie 又是 SameSite=Lax），不加 CORS 头。
  - 忘了密码：团队在服务器上用 `node scripts/teacher.mjs reset-password <用户名>` 重置（见 `deploy/README.md`「老师账号」）。班级和座号见下一条；学生端不登录。
- **班级和座号**（10-09）：一位老师可以建多个班（最多 20 个），导入名单（座号 + 姓名，每班 1–80 人，座号 1–99），发布讲义时选发布到哪些班，一个班一张码。
  - 存储：`<dataDir>/classes.json` 存 `{classes:[{id:'c-'+12 位随机十六进制, owner, name, createdAt, confirmedAt, seats:[{n, name, noAi?}], bindings:{座号: {sid:'s-'+16 位随机十六进制, recoveryHash, tokens, boundAt, confirmedAt}}}]}`，和 `accounts.json` 一样用 `jsonStore`（写排队、临时文件 + 改名、权限 600），不进仓库。班级 id 就是学生链接里的 `c`，猜不到。找回码（6 位，从 `ABCDEFGHJKMNPQRSTUVWXYZ23456789` 里随机取）和学生设备 token（32 字节随机十六进制）都只存 sha256；token 每个座号只留最新 5 个。`noAi: true` 是老师关了这个座号的 AI 写作检查（缺省开着），属于名单不属于绑定。班级的 `confirmedAt` 是老师最近一次建班、换名单时勾两项确认（学校同意、已收回家长告知同意书）的时间，绑定的 `confirmedAt` 是学生选座号时勾「我已读过上面的说明……」的时间，都是毫秒；这项功能之前建的班和选的座号没有。顶层可能有 `purge: [sid]`：绑定已经删掉、学习记录还没删完的 `sid`（见下面「删座号的学习记录」）。
  - 隐私：姓名是未成年人个人信息，只在 `classes.json` 里，只通过班级 owner 登录后的接口返回。学生端的接口和页面只有座号和「已有人」；事件照旧只带 `sid`，日志只记请求计数和耗时，教学建议的汇总里没有姓名和座号。删除班级时名单、座号绑定和这些座号的学习记录一起删。
  - 选了座号才上传（10-09，隐私说明和家长同意书的前提）：「选了座号」= `sid` 现在绑定在某个班的座号上，这个班在讲义的 `meta.classes` 里，讲义已发布，班级和讲义是同一位老师的（后端 `seatedSids`）。内置演示讲义、上传讲义点「只是看看」、老师预览、演示画像都算没选座号：前端只更新本机状态、不发学习事件，写作只做规则检查、不调 `/api/writing-check`；后端兜底，这些 `sid` 的学习事件不写盘（照样 200），写作检查 403。页面报错 `client_error` 照收。
  - AI 写作检查按座号关：家长回执第 2 项（AI 写作检查）选了不同意的，老师在班级页关掉这个座号（`/api/classes/:id/seats/:n/ai`）；关了以后写作检查 403，前端只做规则检查。换名单时留下的座号沿用原来的开关，新座号开着。
  - 删座号的学习记录：清空座号、换名单删掉已进班的座号、删除班级时，先删绑定，再删这些 `sid` 的全部学习事件：`<dataDir>` 里所有 `events-` 开头、`.jsonl` 结尾的文件（各讲义的 `events-<讲义>.jsonl`，以及 `deploy/archive-events.sh`、`archive-sessions.sh` 留下的存档和 `.bak` 备份），解析每行比 `sid` 字段（解析不了的行原样保留），有变化的写临时文件再改名，删空的删掉。服务器自己对事件文件的追加和这里的改写排同一条按文件的写队列，改写期间新到的行不丢；留不留事件的判断也在队列里做，删除之后到的这个 `sid` 的事件已经看不到绑定，不会再写进去。响应带 `deletedEvents`，日志只记条数。删之前，这些 `sid` 和删绑定同一次写盘记进 `classes.json` 的待删列表 `purge`；一个文件出错（磁盘满、读不了）接着删别的，响应多一个 `incomplete: true`（班级页提示服务器会自动再删），日志加错误类型；全部删完才从列表里去掉，没删完的每次到期清理都不看天数再删一遍。
  - 到期清理：后端直接运行时启动后跑一次、之后每 24 小时一次，删掉超过 `CLEANUP_ANON_DAYS`（默认 30）天的页面报错（写盘时 `ts` 不超过收到的时间）和没绑定座号的事件、超过 `CLEANUP_CACHE_DAYS`（默认 30）天的 `llm-cache/`、`advice-cache/` 文件；绑定在座号上的学习事件不按天数删；待删列表 `purge` 里的 `sid` 不看天数全删。规则见 `deploy/README.md`「数据留存和到期清理」。
  - 学生进班：「有效的班级 + 讲义」= 班级存在，讲义已发布、`meta.classes` 里有这个班，班级和讲义是同一位老师的；不满足一律 404。选座号在写队列里按最新的文件再查，同时选同一个座号只有一个成功；同一个班每小时最多 120 次选座号请求。
  - 找回：座号 + 找回码（去掉空白和「-」、转大写后比 sha256，`timingSafeEqual`）→ 同一个 `sid`、新 token。同一个座号 15 分钟内失败 5 次、同一个班 15 分钟内失败 30 次先锁住；和登录一样先记失败再比对，并发请求绕不过去；老师重置找回码时这个座号的次数清零，15 分钟内这个座号也不受整个班那层限次（有人刷错码锁住全班时，老师重置照样管用）。码对了的找回每次都要重写 `classes.json`，同一个座号每小时最多 10 次。找回后前端用 `/api/my-progress` 拿回这个座号在这份讲义里的事件，重建学习进度。
  - 老师端：`/api/events` 要带 `classId`，只返回这个班已选座号的 `sid` 的事件；老师用 `/api/classes/:id` 的名单把 `sid` 对到座号和姓名。清空座号时旧 `sid` 的学习记录一起删掉，老师端下次刷新就没有了；`meta.classes` 里已经删掉的班一律忽略。
- **AI 起草讲解**（`/notes/draft`）：模型 `PIPELINE_MODEL`（默认 deepseek-v4-pro），`PIPELINE_FALLBACKS` 做备选，关闭思考。一次点击把还没有讲解的句子按段落顺序 8 句一批（`NOTES_BATCH`），同时最多 2 批（`NOTES_CONCURRENCY`），每批 60 秒超时；本地用真实模型实测，14 句的文章分 2 批、12 秒、起草 11 句（3 句简单的跳过），句子多的文章要一两分钟，比线上 nginx 的读超时长，所以是异步的：`POST` 只做检查、记次数（按点击算，不按批算），马上返回 `draftId`，模型在后台跑，前端每 1.5 秒查 `/api/notes-drafts/:draftId`，最多查 10 分钟；还在跑时返回已完成几批、共几批，上传页按钮显示「AI 正在起草……第 x / y 批（句子多的文章要一两分钟）」（只有一批时是「AI 正在起草……（大约半分钟）」）；结果只放在内存里，还在跑的不删，结束的保留最近 50 个、10 分钟。发给模型的是还没有讲解的句子（原文、段落、这一句里的注释词、有没有题；注释词取原句里整词出现的，按原句写法，和学生端「给你」便签的判断一样），请它把值得讲的都挑出来（长、结构复杂、容易读错的，有关键生词挡住理解的，作者表明观点或转折的），简单好懂的跳过，不限句数，用大白话、不用语法术语；有注释词挡住理解的，加一句「如果不认识 X 一词，很可能读不懂这句话。」，X 照原句写法，「给你」便签才引得上。除了这一句，草稿里不能用「如果」：「给你」便签在学生答题前就引带「如果」的那一句，不能提前透露词义。带语法术语的、在这一句之外用了「如果」的、句子 id 不在输入里或重复的、少于 20 字或超过 300 字的整条丢掉；模型给了条目却一条都不剩算这一批失败，模型给的是空列表就算这一批起草完了；合起来一条都没有时 `notes` 是 `{}`（上传页显示「AI 这次没有起草新的讲解。」）。每一批第一次在 25 秒内失败、又不是 4xx（上游 5xx、断网、不是 JSON、条目全不合格）才再试一次，60 秒超时和 4xx 不再试；所有批都失败才算失败（「AI 起草暂时不可用，可以先自己写」），有的批失败就返回成功的草稿，再加一句「另有 N 句这次 AI 没能起草，可以过一会儿再点一次「AI 起草讲解」。」。草稿不写进讲义，老师点「保存讲解」走 `/notes` 才写。限次：同一位老师每小时 10 次，同一篇文章每小时 10 次，全站每天（北京时间）100 次。
- **id**：`up-` 加小写字母和数字（如 `up-mg5k2x7a`），符合事件接口的 `handoutId` 规则。
- **管线的调用方式**：`createApp({ buildArticle })` 可以注入，测试用假的；默认懒加载 `../dist-server/article.mjs` 里的 `buildFromArticle`。大模型配置用服务器已有的 Key 和地址，模型 `PIPELINE_MODEL`（默认 deepseek-v4-pro），关闭思考，单次超时 90 秒，缓存目录 `<dataDir>/llm-cache`。管线在独立线程（`server/article-worker.mjs`）里跑，整个任务超过 300 秒就终止线程、任务失败，主线程不做 CPU 密集的事。
- 管线抛出的 `ArticleError` → `400` 或任务 `error`，原样把 message 给老师；其他异常只给老师看「生成失败，请稍后再试」，详细信息写日志。

## 三、前端

  - URL 里的 `h`（`?h=` 或 `#/…?h=`）是打包内置的讲义就直接用；否则请求 `/api/handouts/<h>`（10 秒超时；同源请求自动带上会话 cookie，上传的老师登录后发布前也能在新标签页试做学生端），用 `Handout.parse` 校验后再用。
