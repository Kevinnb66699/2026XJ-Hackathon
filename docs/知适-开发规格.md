# 知适：开发规格（基于团队 PRD）

> 来源：团队的 [知适PRD.md](../知适PRD.md)，加上 10-01 23:00 的四个决定：
> 1. 材料由**老师上传**；
> 2. 适配 = **原文一字不改，只适配支架**；
> 3. 画像**不单独考试**（见 §2）；
> 4. 五个环节都能走通，**只把「学生词」和「精读」做深**。
>
> 讲义来源：**学校**。第一客户是学校英语组。

## 1. 一句话

**一句话定位**（10-01 24:00 前交到群里）：
> 我们为用老师自编外刊讲义学英语的高中生和写讲义的老师，在课后独自读外刊、做打卡作业的场景，解决「一份讲义对全班一刀切」的问题：每个人卡在不同的句子上读不懂，老师却只能随机抽查，看不见谁卡在哪。

**路演钩子**：老师讲义里写着「如果不认识 fret 一词……」。知适把讲义里的「如果」，改成「你」。

## 2. 画像怎么建：不考试，边学边建

团队担心「问卷里加小测会太长，学生没耐心」，这个担心是对的：学生评审说过，诊断超过 5 分钟就会关掉。所以**不单独设小测**，诊断藏在学习本身里：

| 时机 | 学生在做什么 | 顺便得到的画像信号 | 额外耗时 |
|---|---|---|---|
| 开始前 | **3 题问卷**：年级和课程体系 / 读外刊通常卡在哪（生词、长句、段意、作者观点） | 默认先展开哪种支架（未实现：问卷只存在本机，目前不参与适配） | 约 20 秒 |
| 粗读 | 先通读全文，**遇到不认识的词就点一下**（不查释义，只标记）；读完再答每段一道引导问题 | 生词表；哪一段没读懂 | 0（本来就要读） |
| 学生词 | 只出你点过的词，加上老师必练词里你没点的；每张卡片「认识 / 不认识」 | 词汇掌握；混入 1 个假词（上传的文章不放），防止乱点「认识」；先猜后看第一次猜错的词，之后点「认识」也按不认识算 | 0（本来就要背词） |
| 精读 | 卡住了点梯子；原句微题考意思（题目和选项用英文，同老师 Day 2/3「细节理解」） | 卡在哪句、开到第几级 | 0 |

评委在展位上会看到：评委模式的 3 道意思快题（1 道熟词僻义先猜后看、2 道原句题）→ 页面马上变成「你的这一份」，和同学 B 并排对比。这也就是 PRD 里写的「向评委展示用户怎么第一次使用」。

## 3. 用户流程

### 老师端
1. **上传讲义**：粘贴文本或上传 txt，不做 PDF/OCR。
2. 系统通过入库管线（§5）自动列出本周目标，每条都附讲义原话作出处。目标分三级：
   - **必练**：4 句打卡句、15 个核心词、Day 5 写作要求用的表达；
   - **精讲项**：老师「句子分析」里点名的句子和表达；
   - **其他**。
3. 老师点「确认发布」。
4. **教师页**：
   - 首屏是「今天点评这几个人」（随机 + 定向，每人一行原因）；
   - 下面是卡点热力图（按句子，也可以切换按结构）；
   - 最后是「下一届的起点」：建议下一版讲义默认加梯子的句子。

### 学生端（PRD 的五个环节）

| 环节 | 对应讲义 | 深度 | 具体做什么 |
|---|---|---|---|
| ① 问卷 | — | 薄 | 3 题 |
| ② 粗读 | Day 1 泛读 | 薄 | 原文一字不改；先通读全文、点不认识的词（照老师 Day 1「请快速通读全文」），读完再答每段一道引导问题（英文），选项提交前可以随便改，全部选好后一起提交；答错就在题下给出这一段并标出主题句，再错给英文要点，错题换个答案再提交 |
| ③ 学生词 | Day 1 词汇 | **深** | 只练你的词；先猜后看（二选一语境猜义，英文题干、中文选项，同老师 Day 1「中文释义选择」；猜完再显示中文）；熟词僻义（blanket、pending……）一律算难；老师必练词永不跳过 |
| ④ 精读 | Day 2–3 | **深** | 难句旁边是读懂梯子：L1 谁做了什么 → L2 调回正常语序 → L3 简单英文 + 难词中文。关梯子前先在原句上答一道意思题。原句题第一次答错，自动打开梯子第 1 步（不让学生在 3 个选项里换着点蒙对）。第一次就读懂的句子，老师精讲默认收起（可以展开，写明依据）。同类结构之前读懂过，下一句先自己试，答错立刻给梯子。精读中把表达收进「我的表达本」。「篇章结构和写作手法」只做 1 页静态展示 |
| ⑤ 写作 | Day 5 | 中 | 用表达本里的表达和老师要求的表达写 2–3 句。**规则**检查有没有用上；**大模型**判断用得对不对，并附原文例句，再指出最多 3 处可能的语法问题（只引学生写的几个词、标出类型、提示该检查什么），**不替学生改写**。没用对的，下次遇到先自己试（未实现：写作结果目前不回到适配） |
| ⑥ 反馈 | — | 薄 | 太简单 / 刚好 / 太难，加上「我卡在这里，因为……」 |
| ⑦ 下一轮 | — | 演示 | 同一份讲义里，同类结构再遇到先自己试（已实现）；换一份讲义后接着用这一份的画像（未实现）；换一份材料也能用：老师上传任意英文文章（已实现） |

**学生端硬规则**（写进测试）：
- 原文逐字一致；
- 必练项永不收起；
- 选项数不减；
- 不出现语法术语（例外：写作页「可能写错的地方」一栏的类型标签用时态、主谓一致、冠词这类叫法，栏名不写「语法」；老师讲解是老师原话，原样保留）；
- 打卡句交初稿前只给 L1；
- 写作反馈不给改写后的句子；
- 不显示任何等级标签。

## 4. 三条主线（路演）

1. **一刀切**：老师选的这篇社论，批评「一刀切的禁令适得其反」；我们反对一刀切的讲义。
2. **回响**：一份讲义发出去，30 个学生的「如果」回响回来，变成老师下节课的那一页。
3. **表达链**：你读到的表达，要在你自己的写作里活过来。

**普惠**：稀缺的不是钱，是老师对每个学生的注意力；普通高中大班更缺。学生端不调用大模型，每多一个学生几乎不增加成本。（更正：写作检查是按学生调用模型的，路演不说这句，见 `docs/路演PPT大纲.md`「和仓库对口径」。）

## 5. 技术架构

```
老师侧（离线，每份讲义一次）              学生侧（运行时，纯规则）                数据回流
讲义文本 → 规则切节 → 大模型起草        行为事件 → personalize()               事件 → POST /api/events
→ 校验器 → 老师确认 → handout.json      纯函数 → 渲染「你的这一份」             → 教师页热力图 / 点评名单
                                        写作检查：规则 + 服务器代理调用大模型
```

- **前端**：Vite 4 + React 18 + TypeScript + Tailwind。兼容本机的 Node 16。不引用任何外部 CDN 或字体。
- **数据契约**：[shared/schema.ts](../shared/schema.ts)（zod）。管线、前端、测试、校验器共用这一份。
- **管线** `pipeline/`：
  - 规则负责切节，并把打卡句、填空位置、核心词表直接标为必练；
  - 大模型使用组委会提供的 TokenDance token（OpenAI 兼容接口，JSON 模式，temperature=0），负责起草梯子、意思题、表达和段意题；
  - **校验器**检查：原句和出处是讲义原文的子串；L1 是原句子串；答案在选项内；
  - 每条数据记录 `provenance`；模型响应缓存后可用 `--replay` 复跑，并生成 `report.md`。
  - **10-02 11:00 还不稳，就退回人工起草 JSON**，但同样要过校验器。
- **极小后端** `server/index.mjs`：
  - Express 提供 `POST /api/events`（追加写 JSONL）、`GET /api/heatmap`、`POST /api/writing-check`（服务器代理调用大模型，8 秒超时就回落到规则反馈）；
  - API Key 只放在服务器的 `.env` 里，不提交。
- **部署**：队长的国内服务器。Nginx 托管静态文件，`/api` 反代到 Node。笔记本本地再跑一份兜底。
- **测试**：Vitest 测 §3 的硬规则；队友 2 写 15–20 条「画像 → 期望结果」用例；用 `npm run check` 一键跑完。
