# 老师上传文章：设计与接口约定

> 目标：老师粘贴任意一篇英文文章（标题可不填，不填由 AI 起一个；可选填必练词、教学重点），AI 起草读懂支架，程序校验，老师预览后发布，学生扫码就能用。比赛期间评委可以用自己手机里的文章当场试；10-04 起上传只对受邀老师开放。
> 三部分（管线 / 后端 / 前端）并行开发，**接口以本文为准**。

## 流程

1. 老师在 `#/upload` 粘贴文章，填邀请码，提交。比赛期间不设口令、谁都能体验；10-04 比赛结束后改成**只对受邀老师开放**，邀请码由知适团队发放（服务器 `.env` 的 `UPLOAD_INVITES`，见 `deploy/README.md`「发邀请码」）。
2. 后端建一个生成任务，立即返回 `jobId` 和写讲解、改题目用的 `editKey`（前端存进本机上传历史）；前端每 1.5 秒查一次进度（切句 → 起草第 x / n 段 → 修正 → 校验）。
3. 生成完成：讲义存到服务器，显示入库报告（多少梯子、题目、注释，被校验拦下了什么），可以先预览学生端。
4. （可选，发布前后都行）老师按句写讲解，或点「AI 起草讲解」请 AI 给还没有讲解的句子写一稿（点一次就把值得讲的都起草，简单好懂的跳过；句子多时分批起草，按钮上显示「第 x / y 批」）。草稿只填进编辑区、标「AI 草稿，待你确认」，老师看过、改好，点「保存讲解」才存进讲义，学生才看得到（保存就算老师认可）。只有上传这篇文章的那台设备能写讲解（见下文「编辑口令」）。写了讲解的句子和演示讲义一样：讲解在学生答完这一句的题后显示，没有题的句子直接显示；有题、又不是重点句的，第一次就答对、没开梯子的学生讲解先收起；讲解里有一句带「如果」、照原句写法点名这一句的某个注释词、不带语法术语，这个词又正好是他不认识的，他答题前就会多一张「给你」便签，引的就是这一句，所以这一句不能写词义。没写讲解的句子两样都没有。已经打开页面的学生要重新打开才看得到新讲解。
   同一页下面还能改 AI 起草的原句题、梯子和段意题（10-03，提交 e59f79d）：同样只有上传的那台设备能改，服务器按入库的规则再校验，不合格的按字段标红、一处都不写（见下文「改题目和梯子」）。
5. 老师点「发布」（要编辑口令，只有上传的那台设备能发布；没发布的讲义学生打不开），页面给出学生链接和二维码（`/?h=<id>#/student`），也给老师端的链接（评委模式 10-04 已下线）。

## 一、管线：`pipeline/article.ts`

```ts
export interface ArticleInput {
  title: string           // 可以为空：请模型起一个英文标题（titleByModel），失败时用 deriveTitle 取原文第一句
  text: string            // 英文原文，段落之间空一行（没有空行时按单个换行分段）
  mustWords?: string[]    // 老师必练词（可选）
  checkIns?: string[]     // 重点句（可选，从原文复制，可以只是句子的一部分；上传页已不再填写，只为旧页面保留）
  focus?: string          // 教学重点（可选，自由文字，交给模型参考）
}
export type ArticleProgress =
  | { stage: 'split'; message: string }
  | { stage: 'draft'; done: number; total: number }
  | { stage: 'repair' | 'validate'; message: string }
  | { stage: 'done' }
export interface ArticleReport {
  paragraphs: number; sentences: number
  ladders: number; questions: number; gists: number
  words: number; guesses: number; expressions: number
  checkIns: string[]                              // 最终的重点句 id
  mustWords: { term: string; found: boolean }[]   // 老师必练词有没有在原文里找到
  repaired: string[]; dropped: string[]; warnings: string[]
  errors: number; model: string; seconds: number
}
export class ArticleError extends Error {}        // message 是给老师看的中文
export function splitArticle(text: string): { n: number; sentences: { id: string; text: string }[] }[]
export async function titleByModel(cfg: LlmConfig, text: string): Promise<string> // 没填标题时请模型起的英文标题
export function deriveTitle(text: string): string // 模型起不成时的标题（原文第一句）
export async function buildFromArticle(input: ArticleInput, opts: {
  id: string                                      // 讲义 id，形如 up-xxxx
  llm: LlmConfig
  onProgress?: (p: ArticleProgress) => void
  draft?: (p: ParagraphInput, focus?: string) => Promise<{ data: DraftParagraph; model: string }> // 测试时注入
}): Promise<{ handout: Handout; report: ArticleReport }>
```

- **标题**：没填就请模型起一个英文标题（issue #23；#26 从中文改成英文，提示词 `title-v2`，送整篇原文，和起草同时进行），像外刊文章的标题（提示词要 2–8 个词，比如「Gardens Grow in Schoolyards」）。校验：不超过 60 个字符，2–10 个英文单词，只能用英文字母、数字和常见标点（不能有中文、双引号和换行，撇号可以），不合格时让模型重写一次，单次限时 20 秒。模型超时、出错或两次都不合格，就用第一段的第一句，也就是 S01（分段规则见上、切句规则同下；段落之间有空行时，硬换行粘贴的段落也取整句）；超过 60 个字符就在词的边界截断、加「…」（连「…」不超过 60）。讲义标题、写作题目、meta、上传历史都用它。
- **原文一字不改**：段内的换行合并成一个空格，其余字符原样保留。
- **限制**（超出就抛 `ArticleError`）：全文 200–8000 字符；英文字母要占多数；最多 12 段、60 句；单句不超过 400 字符；必练词最多 20 个，重点句最多 8 句。
- **切句**：在 `. ! ?`（后面可跟引号或括号）之后、下一个字符是大写字母、数字或引号的位置切开；Mr. / Dr. / U.S. / e.g. 等缩写不切。
- **起草**用新的提示词（版本 `article-v1`），不动现有讲义的 `draft-v1` 缓存：
  - 原句题、段意题的题干和选项都用英文（B1），正确项必须改写，不能照抄原句关键词；选项长度接近；
  - 先猜后看：题干 `What does “X” most likely mean here?`，两个选项用中文；
  - 学生端的中文和英文都不能有语法术语（中文见 `shared/terms.ts`；英文避免 clause / inversion / appositive / subject / predicate / grammar）；
  - 结构标签 `tag` 由模型按自己的分析填写（没有老师句子分析）。
- **重点句**（字段 `checkIn`；演示讲义里是老师的打卡翻译句，界面上 10-03 起叫「重点句」，issue #24）：上传页不再填写（10-02，issue #7），所以一般都是自动挑。老师给了就按原文匹配（忽略大小写和多余空白），匹配不到的写进 warnings。没给就自动挑：有梯子和原句题的句子里取最长的，最多 3 句，尽量分散在不同段落。重点句是 `tier: 'must'`、`checkIn: true`。
- **必练词**：用 `findForms` 在原文里找，找到的交给模型（必须出注释），然后标 `teacherCore: true`、`tier: 'must'`。
- **表达**：用模型起草的表达，匹配规则用 `patternFor` 生成。写作要求取前 3 个，写作题目为「用这篇文章学到的表达写 2–3 句：<标题>」。
- **校验**：照 `ingest.ts` 的流程，先用 `repairLadderL1` 自我修正，再用 `validateHandout` 校验，不合格的模型产出自动剔除并写进 `dropped`。最后不能有 error。
- **讲义字段**：`rights` 写「老师上传的文章，仅供本班学习使用」，`sources` 为空，`day` 统一为 2。
- **构建**：`npm run build` 额外输出 `dist-server/article.mjs`（vite SSR 构建，zod / undici 走外部依赖），Node 20 能直接 `import()`。`dist-server/` 不进 git。

## 二、后端：`server/index.mjs`

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| POST | `/api/uploads` | `{device, invite, title?, text, mustWords?, checkIns?, focus?}`（`invite` 是邀请码；`title` 可以为空，不超过 100 个字符；上传页不再发 `checkIns`） | `202 {jobId, editKey}`（`editKey` 是这篇的编辑口令，只在这个响应里给）；依次检查：没有 Key `503 {error}`；`device` 不对 `400 {error}`；服务器没配置邀请码 `403 {error:'上传目前只对受邀老师开放'}`；邀请码没带或不对 `403 {error:'邀请码不对，请向知适团队确认'}`；输入不合格 `400 {error}`；已有任务在跑、超过次数限制 `429 {error}` |
| GET | `/api/uploads/:jobId` | 请求头 `X-Edit-Key: <editKey>` | `{status:'running', progress}` 或 `{status:'done', handoutId, title, report}`（`title` 是讲义的标题，没填时是管线生成的） 或 `{status:'error', error}`；没带口令、口令不对、任务找不到都是 `404 {error:'找不到这个生成任务，请重新提交'}`；返回的任务对象里没有口令 |
| GET | `/api/handouts/:id` | 没发布的要带请求头 `X-Edit-Key: <editKey>` | 讲义 JSON（`Cache-Control: no-cache`，老师改过以后学生重新打开就拿到新的）；发布了的谁都能读；没发布的口令对不上、不存在都是 `404 {error:'没有这份讲义'}`（不暴露「存在但没发布」） |
| POST | `/api/handouts/:id/publish` | `{key}`：`key` 是 `editKey` | `{ok:true}`；讲义不存在 `404 {error:'没有这份讲义'}`；口令不对、这份讲义没有口令 `403 {error:'只有上传这篇文章的那台设备能发布'}` |
| POST | `/api/handouts/:id/notes` | `{key, notes: {S01: '…', …}}`：`key` 是上传时拿到的 `editKey`；给了的句子写进去（去掉首尾空白），空字符串就删掉，没给的不动；句子 id 必须是这份讲义里的，每条不超过 600 字（`MAX_NOTE`） | `{ok:true, count}`（`count` 是现在有讲解的句子数）；讲义不存在 `404 {error}`；口令不对、这份讲义没有口令 `403 {error:'只有上传这篇文章的那台设备能写讲解'}`；格式不对、句子 id 不对、太长 `400 {error}`，文件不改；写文件失败 `500 {error}` |
| POST | `/api/handouts/:id/edits` | `{key, sentences?: {S03: {question?: {prompt, options, answer}, ladder?: {subject, predicate, l2, plain, glosses: [{term, zh}]}}}, paragraphs?: {2: {gist: {prompt, options, answer}}}}`：只发改过的块，给了的整块换掉（题目 id 不变） | `{ok:true, handout}`；口令不对 `403 {error:'只有上传这篇文章的那台设备能改题目和梯子'}`；不是上传的讲义或不存在 `404`；有一处不合格 `400 {error, fields: {'S03.ladder.subject': '梯子第 1 步的「谁」必须是原句里的原话', …}}`，一处都不写（详见 `deploy/README.md`） |
| POST | `/api/handouts/:id/notes/draft` | `{key, device}` | `202 {draftId}`：建一个起草任务，马上返回，前端每 1.5 秒查下一行；讲义不存在 `404`；口令不对 `403`；`device` 不对、每一句都已经有讲解 `400`；没有 Key `503`；超过次数限制 `429` |
| GET | `/api/notes-drafts/:draftId` | | `{status:'running', done, total}`（已完成的批数 / 共几批）或 `{status:'done', notes: {S03: '…', …}, model}`（AI 起草的讲解，只回给老师当草稿，不写进讲义；模型给的是空列表时 `notes` 是 `{}`；有的批没起草成时多一个 `message:'另有 N 句这次 AI 没能起草，可以过一会儿再点一次「AI 起草讲解」。'`）或 `{status:'error', error:'AI 起草暂时不可用，可以先自己写'}`；`draftId` 是 24 位随机十六进制，找不到 `404` |

- **防滥用**：要邀请码（`UPLOAD_INVITES`，逗号分隔，少于 8 个字符的不用；没配置就谁都不能上传；比对的是 sha256 哈希，码本身不进 meta、日志和响应）；同一时间只跑一个任务；同一设备每小时最多 5 篇（`device` 由上传页随机生成，存在 localStorage）；全站每天（北京时间）最多 60 篇。没有公开列表；没发布的讲义只有上传的那台设备（带口令）能打开，发布后拿到链接就能打开。
- **存储**：`<dataDir>/handouts/<id>.json` 存讲义，`<id>.meta.json` 存 `{id,title,createdAt,published,report,editKey}`（`title` 取讲义的标题；发布时改 meta 也是先写临时文件再改名，里面有唯一一份编辑口令）。任务只放在内存里，保留最近 20 个；同一时间只跑一个任务。
- **老师讲解**：存在讲义每一句的 `teacherNote`（和演示讲义同一个字段，不记哪几条是 AI 起草的），学生端照演示讲义的规则收起讲解、给「给你」便签。同一份讲义的保存排队，每次写一个随机名字的临时文件再改名，学生这时打开也不会读到半份。
- **改题目和梯子**（`/edits`，10-03）：老师能改原句题（题干、选项、正确答案）、梯子（第 1 步「谁」「做了什么」，第 2、3 步，难词的中文意思）和段意题；规则和校验器一致：第 1 步必须是原句原话，选项 2–4 个、不空、不重复，答案序号在范围内，题目、选项、梯子里不能有语法术语（`shared/terms.ts` 那张表；老师讲解不受此限）。不能改的：「先猜一猜」词题、注释词；不能增删选项和难词。改过的块来源记成 `{by:'human', reviewedBy:'teacher'}`。和 `/notes` 排同一条保存队；学生已经答过的记录不变。
- **编辑口令**：讲义 id 就在学生链接里，所以光有 id 不能写讲解、发布、看全班记录。`POST /api/uploads` 时随机生成一个 `editKey`，存进这篇的 meta，也存进上传那台浏览器的上传历史（localStorage），老师不用记、不用输入；查进度、读讲义的接口都不返回它。POST 的 `/publish`、`/notes`、`/notes/draft` 和 `/edits` 放在请求体的 `key` 里，对不上就 403；GET 的查进度（`/api/uploads/:jobId`）、读没发布的讲义（`/api/handouts/:id`）和读全班学习记录（`/api/events`）放在请求头 `X-Edit-Key` 里（不放进查询串，免得进 nginx 访问日志），前两个对不上 404，读学习记录对不上 403。这个功能之前上传的讲义没有口令，不能写讲解、改题目、发布，也看不了学习记录。
- **AI 起草讲解**（`/notes/draft`）：模型 `PIPELINE_MODEL`（默认 deepseek-v4-pro），`PIPELINE_FALLBACKS` 做备选，关闭思考。一次点击把还没有讲解的句子按段落顺序 8 句一批（`NOTES_BATCH`），同时最多 2 批（`NOTES_CONCURRENCY`），每批 60 秒超时；本地用真实模型实测，14 句的文章分 2 批、12 秒、起草 11 句（3 句简单的跳过），句子多的文章要一两分钟，比线上 nginx 的读超时长，所以是异步的：`POST` 只做检查、记次数（按点击算，不按批算），马上返回 `draftId`，模型在后台跑，前端每 1.5 秒查 `/api/notes-drafts/:draftId`，最多查 10 分钟；还在跑时返回已完成几批、共几批，上传页按钮显示「AI 正在起草……第 x / y 批（句子多的文章要一两分钟）」（只有一批时是「AI 正在起草……（大约半分钟）」）；结果只放在内存里，还在跑的不删，结束的保留最近 50 个、10 分钟。发给模型的是还没有讲解的句子（原文、段落、这一句里的注释词、有没有题；注释词取原句里整词出现的，按原句写法，和学生端「给你」便签的判断一样），请它把值得讲的都挑出来（长、结构复杂、容易读错的，有关键生词挡住理解的，作者表明观点或转折的），简单好懂的跳过，不限句数，用大白话、不用语法术语；有注释词挡住理解的，加一句「如果不认识 X 一词，很可能读不懂这句话。」，X 照原句写法，「给你」便签才引得上。除了这一句，草稿里不能用「如果」：「给你」便签在学生答题前就引带「如果」的那一句，不能提前透露词义。带语法术语的、在这一句之外用了「如果」的、句子 id 不在输入里或重复的、少于 20 字或超过 300 字的整条丢掉；模型给了条目却一条都不剩算这一批失败，模型给的是空列表就算这一批起草完了；合起来一条都没有时 `notes` 是 `{}`（上传页显示「AI 这次没有起草新的讲解。」）。每一批第一次在 25 秒内失败、又不是 4xx（上游 5xx、断网、不是 JSON、条目全不合格）才再试一次，60 秒超时和 4xx 不再试；所有批都失败才算失败（「AI 起草暂时不可用，可以先自己写」），有的批失败就返回成功的草稿，再加一句「另有 N 句这次 AI 没能起草，可以过一会儿再点一次「AI 起草讲解」。」。草稿不写进讲义，老师点「保存讲解」走 `/notes` 才写。限次：同一设备每小时 10 次，同一篇文章每小时 10 次，全站每天（北京时间）100 次。
- **id**：`up-` 加小写字母和数字（如 `up-mg5k2x7a`），符合事件接口的 `handoutId` 规则。
- **管线的调用方式**：`createApp({ buildArticle })` 可以注入，测试用假的；默认懒加载 `../dist-server/article.mjs` 里的 `buildFromArticle`。大模型配置用服务器已有的 Key 和地址，模型 `PIPELINE_MODEL`（默认 deepseek-v4-pro），关闭思考，单次超时 90 秒，缓存目录 `<dataDir>/llm-cache`。管线在独立线程（`server/article-worker.mjs`）里跑，整个任务超过 300 秒就终止线程、任务失败，主线程不做 CPU 密集的事。
- 管线抛出的 `ArticleError` → `400` 或任务 `error`，原样把 message 给老师；其他异常只给老师看「生成失败，请稍后再试」，详细信息写日志。

## 三、前端

- **讲义加载**（`src/data/index.ts`）：
  - `export let currentHandout`，新增 `loadCurrentHandout()`。
  - URL 里的 `h`（`?h=` 或 `#/…?h=`）是打包内置的讲义就直接用；否则请求 `/api/handouts/<h>`（10 秒超时；本机存着这篇的编辑口令就带上请求头 `X-Edit-Key`，老师发布前也能在新标签页试做学生端），用 `Handout.parse` 校验后再用。
